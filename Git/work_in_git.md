Если после выполнения команды `git reset --hard` изменения все равно остаются доступными для отправки (`push`), есть несколько возможных причин, почему это происходит:

### Возможные причины:

1. **Вы не сбросили все коммиты, которые ожидают отправки:**
   Команда `git reset --hard` сбрасывает только **текущую ветку** к определённому состоянию. Если на этой ветке остаются другие коммиты, которые не были отправлены (например, изменения в несколько коммитов), то `push` всё равно будет доступен для отправки этих коммитов.

   Проверьте состояние локальной ветки командой:
   ```bash
   git log
   ```
   Убедитесь, что все коммиты, которые вы не хотите отправлять, были откатаны.

   Для отката нескольких коммитов выполните:
   ```bash
   git reset --hard HEAD~N
   ```
   Где `N` — это количество последних коммитов, которые нужно удалить.

2. **Изменения в других ветках:**
   Вы могли переключиться на другую ветку, и изменения на другой ветке ожидают отправки. Убедитесь, что вы работаете с нужной веткой. Проверьте текущую ветку командой:
   ```bash
   git branch
   ```
   Если это не та ветка, выполните:
   ```bash
   git checkout <нужная ветка>
   ```

3. **Изменения на удалённой ветке:**
   Если после выполнения `git reset --hard` изменения всё ещё готовы к отправке, это может быть связано с тем, что на удалённой ветке есть новые коммиты, которые нужно синхронизировать. Попробуйте сначала получить изменения с удалённой ветки:
   ```bash
   git fetch origin
   ```
   И затем проверьте состояние командой `git status`.

4. **Изменения в подмодулях или других репозиториях:**
   В вашем проекте могут быть подмодули или другие репозитории, которые требуют отдельного `push`. Убедитесь, что вы сбросили все изменения во всех подмодулях.

5. **Локальные изменения в файлах, которые не учтены:**
   Даже после сброса коммитов могут остаться неиндексированные локальные изменения. Убедитесь, что после `git reset --hard` нет изменений в файлах:
   ```bash
   git status
   ```

6. **Неправильная цель для `reset`:**
   Возможно, вы выполняли `git reset --hard` не на той ветке или не откатили нужные коммиты. Чтобы откатить изменения, которые были сделаны до определённого коммита, убедитесь, что вы правильно указываете `HEAD` или другой хеш коммита.

# Проверка состояния:
Чтобы убедиться, что ваш репозиторий находится в нужном состоянии после выполнения сброса, выполните команду:
```bash
git status
```
Она покажет, какие изменения ещё ожидают отправки или какие файлы были изменены.

# Пример отката всех локальных коммитов:
1. Откат всех последних коммитов:
   ```bash
   git reset --hard origin/<branch_name>
   ```
   Эта команда откатит все локальные коммиты до состояния удалённой ветки.

2. Проверьте статус:
   ```bash
   git status
   ```

Теперь, если всё сделано правильно, ничего не должно оставаться для отправки (`push`).




# Смена репозитория

1. Добавить новый удалённый репозиторий
   ```bash
   git remote add new-origin <URL_нового_репозитория>
   ```
2. Удалить старый удалённый репозиторий
   ```bash
   git remote remove origin
   ```
   
3. Переименовать новый удалённый репозиторий в origin

   ```bash
   git remote rename new-origin origin
   ```
   
4. Проверить, что новый удалённый репозиторий установлен как origin

   ```bash
   git remote -v
   ```
