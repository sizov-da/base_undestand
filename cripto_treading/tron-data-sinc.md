Хорошо, чтобы максимально ускорить синхронизацию ноды Tron, мы применим самый эффективный метод — использование готового снимка (snapshot) базы данных. Это позволит пропустить долгий процесс загрузки и обработки блоков с самого начала.

Вот пошаговый план:

### Шаг 1: Остановите и удалите текущую ноду

Сначала нужно полностью остановить и удалить контейнер, чтобы он не мешал работе с файлами.

```bash
docker-compose down
```

### Шаг 2: Очистите старые данные

Удалите всё содержимое папки с данными блокчейна. Это важно, чтобы не было конфликтов со старыми файлами.

```bash
sudo rm -rf ./nods/data/tron/*
```

### Шаг 3: Скачайте и распакуйте снимок данных

1.  Перейдите в директорию, где будет лежать база данных:
    ```bash
    cd ./nods/data/tron
    ```

2.  Скачайте самый свежий снимок данных mainnet. Используйте `aria2c` для быстрой многопоточной загрузки (если он не установлен, используйте `wget` или установите `aria2c` через `sudo apt install aria2`).
    https://developers.tron.network/docs/main-net-database-snapshots - это официальный источник снимков базы данных Tron.

    ```bash
    # Рекомендуется: быстрая загрузка с помощью aria2c
    aria2c -x 16 "https://mainnet-snapshot.tronscan.org/fullnode/latest.tgz"

    # Альтернатива: стандартная загрузка с помощью wget
    # wget -O latest.tgz "https://mainnet-snapshot.tronscan.org/fullnode/latest.tgz"
    ```

3.  Распакуйте архив. В результате у вас появится папка `output-directory`.
    ```bash
    tar -zxvf latest.tgz
    ```

4.  Переместите содержимое `output-directory` на уровень выше, а саму папку и архив удалите.
    ```bash
    mv output-directory/* .
    rmdir output-directory
    rm latest.tgz
    ```

5.  Вернитесь в корневую директорию вашего проекта.
    ```bash
    cd ../../.. 
    ```

### Шаг 4: Установите правильные права (Очень важно)

Так как вы скачивали файлы от имени `root`, нужно снова назначить владельцем пользователя, от которого будет работать контейнер. В вашем `docker-compose.yml` для `tron-node` не указан `user`, значит, он будет запускаться от `root` внутри контейнера. Но чтобы избежать любых проблем с правами, лучше явно задать их для хост-машины.


```bash
# Если вы снова закомментировали user: "1000", то права можно не менять.
# Но если вы планируете его использовать, выполните:
sudo chown -R 1000:1000 ./nods/data/tron
```

### Шаг 5: Запустите ноду

Теперь можно запускать `docker-compose`. Нода запустится с уже почти синхронизированной базой данных и ей останется докачать лишь самые последние блоки.

```bash
docker-compose up -d tron-node
```

После выполнения этих шагов ваша нода должна полностью синхронизироваться в течение нескольких минут, а не часов или дней.



Ошибка `-bash: aria2c: command not found` означает, что утилита `aria2c` для многопоточной загрузки не установлена в вашей системе.

У вас есть два варианта:

### 1. Установить `aria2c` (Рекомендуется для скорости)

Вы можете легко установить ее на Ubuntu с помощью следующей команды:

```bash
sudo apt-get update && sudo apt-get install -y aria2
```

После завершения установки, повторите команду для скачивания снимка:

```bash
aria2c -x 16 "https://mainnet-snapshot.tronscan.org/fullnode/latest.tgz"
```

### 2. Использовать `wget` (Альтернатива)

Если вы не хотите устанавливать новые пакеты, вы можете использовать `wget`, который обычно предустановлен. Этот способ может быть медленнее.

```bash
wget -O latest.tgz "https://mainnet-snapshot.tronscan.org/fullnode/latest.tgz"
```

После того как файл `latest.tgz` будет скачан одним из этих способов, вы можете продолжить выполнение следующих шагов из предыдущей инструкции (распаковка архива, перемещение файлов и запуск ноды).
